# Next.js リファレンスアーキテクチャガイド

AI コーディングエージェント（Claude Code など）を使って Next.js の業務アプリケーションを開発する際に、**実装の拠り所とするアーキテクチャ**を定義したリファレンスドキュメントです。

## これは何か

`docs/nextjs-reference-architecture.md` に、以下を前提とした Next.js アプリケーションの参照アーキテクチャをまとめています。

- Next.js 16 (App Router) / Prisma / PostgreSQL / Auth.js
- ビジネスロジックを持つ業務アプリケーション（DB への CRUD 操作、ユーザー認証、権限管理あり）
- コンテナとして実行し、ローカル開発環境・クラウド上の CaaS の両方で動作させる

ディレクトリ構成、各層（Presentation / Application / Domain / Infrastructure）の責務分離、Server Actions の書き方、認証・認可、コンテナ化、セキュリティ・可用性・運用監視などの非機能要件まで、実装時に判断がブレやすいポイントを一つずつ決めています。

## なぜ必要か

AI コーディングエージェントに実装を依頼すると、同じような要件でも実行ごとに異なるアーキテクチャ（ディレクトリ構成、データ取得方法、エラーハンドリングの流儀など）を採用してしまうことがあります。これは以下のような問題につながります。

- レビューコストが上がる（毎回違うパターンを確認する必要がある）
- 機能追加のたびに既存コードとの一貫性が崩れる
- 「なぜこの設計にしたか」が実装者（エージェント）の中にしかなく、再現性がない

このガイドを AI エージェントに**必ず参照させる**ことで、実装のブレを抑え、レビューアが確認すべき観点を固定できます。

## 対象読者

- Next.js の業務アプリケーションを AI コーディングエージェントと一緒に開発するエンジニア
- チームの実装標準を揃えたいテックリード・アーキテクト

## 使い方

### 1. AI コーディングエージェントに参照させる

このリポジトリ（または該当ファイル）をプロジェクトに取り込み、エージェント用の指示ファイルから参照させます。

**Claude Code の場合（`CLAUDE.md`）:**

```markdown
## アーキテクチャ

実装前に必ず `docs/nextjs-reference-architecture.md` を読み、そこに定義されたレイヤー構成・
ディレクトリ構成・コーディング規約に従うこと。ドキュメントに明記がない判断が必要な場合は、
既存の類似 feature の実装パターンを踏襲し、それでも判断がつかない場合は人間に確認すること。
```

その他のツール（Cursor の `.cursorrules`、GitHub Copilot の `AGENTS.md` など）でも同様に、起動時に読み込む指示ファイルからこのドキュメントへのパスを明記してください。

### 2. 人間のオンボーディング資料として使う

新しくプロジェクトに参加するメンバーが、実装方針・ディレクトリ構成の意図をキャッチアップするための資料としても使えます。

### 3. プロジェクト固有の内容に調整する

このガイドは汎用的なテンプレートです。**そのまま使う前に、必ず以下を確認してください。**

1. ガイド末尾の **19. 今後の拡張ポイント（未決定事項）** に列挙されている項目（マルチテナント要否、レート制限の実装場所、デプロイ先 CaaS の確定など）は、プロジェクトの要件に応じて決定し、ガイド本文に反映する。
2. 本文中の **`> 【検討事項】`** で示された箇所は、要件によって採用方式が変わる部分です。決定した方式をガイドに書き戻し、「検討事項」の記載を削除してください。
3. 技術スタックが異なる場合（例: MySQL を使う、認証を Clerk にする等）は、該当章を書き換えてください。

## Next.js のバージョンに関する注意

このガイドは Next.js 16（2026年8月時点の最新系）の仕様（`proxy.ts`、非同期 `params`、Cache Components など）に基づいています。Next.js の破壊的変更（メジャーバージョンアップ）が入った際は、ガイド本文（特に 0 章・3 章・6.3 節）の記載が古くなっていないか見直してください。
